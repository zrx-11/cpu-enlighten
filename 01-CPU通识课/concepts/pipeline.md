# 流水线

- **难度**：进阶 | **涉及章节**：第 15、16 章

## 一句话定义
流水线是把一条指令的执行拆成若干段、让不同指令同时占着不同段干活的组织方式。

## 为什么重要
它是"不靠提主频也能提速"的第一件法宝。理解流水线，才能理解为什么 CPU 里有一堆看起来"多出来"的寄存器、为什么分支预测错了代价那么大。

## 图示
```mermaid
flowchart LR
  IF[取指] --> ID[译码]
  ID --> EX[执行]
  EX --> MEM[访存]
  MEM --> WB[写回]
```
看图说明：五段像五道工序，每拍每段都有指令在做事。理想状态下每拍完成一条，而不是五拍一条。

## 详解
经典五级：取指、译码、执行、访存、写回。前一条在写回时，后一条正在访存，再后面在执行——同时有五条指令在飞。

提速来自并行，不来自单条变快。代价是三类冲突：结构冲突（两个指令抢同一个部件）、数据冲突（后一条要用前一条还没写回的结果）、控制冲突（遇到分支不知道下一条在哪）。

解决办法：转发（把结果直接送过去，不等写回）、停顿（插气泡）、分支预测（猜方向，猜错就清空流水线）。级数越多，猜错的惩罚越大——Pentium 4 深流水追求高主频，最后被功耗和失误率反噬。

## 常见误解
- 别以为流水线级数越多越快。级数换主频，但每级的开销与预测代价也在涨。
- 别以为流水线等于多核。它只是单核内部的并行。
