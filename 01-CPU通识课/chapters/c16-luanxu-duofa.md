# 第 16 章：乱序执行与多发射——把流水线喂饱

- **难度**：★★★ | **学时**：0.9 小时 | **前置**：第 15 章

## 学习目标
- 能区分数据相关与结构相关，并说明它们为什么让流水线停顿
- 能用保留站、重命名寄存器、ROB 三个部件解释乱序执行
- 能解释多发射与转移猜测各自解决什么问题

## 一句话核心
乱序执行的秩序是：乱着做，按原顺序交账。保留站负责乱，ROB 负责收，重命名寄存器负责中间账。

## 零基础讲解
### 为什么要乱
流水线最怕停顿。相邻两条指令，后一条要用前一条的结果，这叫数据相关（写后读 RAW），后一条只能等。两条都要用唯一的乘法器，这叫结构相关，也只能等。等，就是流水线空转。

既然 A 和 B 相关、A 和 C 不相关，那就让 C 先上。这种由硬件判断相关性、重排执行顺序的技术叫动态调度，做出来的流水线叫动态流水线；反之是静态流水线。手机、桌面的 CPU 基本都是动态的，只有低端嵌入式还用静态。

### Tomasulo 的三个部件
1966 年 IBM 360/91 用的 Tomasulo 算法，是这一切的老祖宗。

保留站（也叫发射队列）在指令队列和计算单元之间，每条待执行的指令占一格，格里记三样：操作类型、已就绪的源操作数数值、还没就绪的源操作数的"生产者编号"。每拍扫一遍，谁的源操作数齐了就送谁去算。

寄存器堆里每个寄存器也加一个指针，指向最后会写它的那个保留站单元。

算完的结果走公共数据总线（CDB）广播回去：所有等这个结果的保留站单元、所有指向它的寄存器，一次全更新。这就是"借道超车"能成立的原因——结果不用挨个通知。

重命名寄存器是这套机制的点睛。软件看得见的叫物理（架构）寄存器，保存最终结果；内部另有一套重命名寄存器，存中间结果。同一个架构寄存器被多条指令反复写，内部各用各的副本，写后读的假依赖就消失了。这叫寄存器重命名。

### ROB：乱着做，按序交
乱序最怕收不了场：一旦某条指令出错（除零、缺页），后面的指令可能已经把状态改乱了。

重排序缓存（ROB）按程序原始顺序排队，在执行之后加一个提交阶段。执行结果先写重命名寄存器，只有走到提交阶段，才写进物理寄存器。正常指令提交后出队；出错的那条，检查 ROB 队首就知道是谁，它后面的指令一律不提交。

所以乱序执行的三句话：有序取指、乱序执行、有序提交。对程序员透明，结果和顺序执行完全一致。

典型结构至少四级：取指、译码（分派到不同发射队列）、发射（挑就绪的送计算单元）、执行（结果经总线写回）。看到材料里出现"发射队列"，基本可以断定这是动态流水线。龙芯用的是统一寄存器堆加译码端重命名表的结构。

### 多发射：一条流水线加宽
多发射不是多条流水线，是把每一级加宽，一拍处理多条指令：取指一次取几条，译码同时分析几条并分到不同队列，发射每拍从各队列各发一条，执行有多个计算单元并行。

书里的比喻很顺：静态流水线是单车道，动态流水线允许超车，多发射是变成多车道齐头并进。

龙芯 3A4000 后端有 8 条执行流水线，峰值 8 操作/周期：每周期最多 4 个定点、2 个浮点/向量、2 个访存。

### 转移猜测：先猜再善后
转移（分支）指令会让程序分叉：要么顺序执行下一条，要么跳到目标地址。多发射一次取好几条，遇到分支就不知道后面该不该取。

办法是猜。最简单的猜"不跳"，成功率约五成，等于白猜一半。高端的用分支目标缓冲器（BTB）记住这条分支上次跳到哪，下次直接照着取，成功率能到九成以上。

猜错怎么办？靠 ROB：猜错路径上的指令不提交，清掉重来。这就是"激进优化 + 善后处理"的思路——先按大概率把流水线喂饱，错了再擦掉，平均下来还是赚。

## 图示
```mermaid
flowchart LR
  IF[取指] --> ID[译码 / 分派]
  ID --> RS[保留站<br/>按就绪挑指令]
  RS --> EX[计算单元 ×N]
  EX -->|CDB 广播| RS
  EX --> ROB[ROB<br/>按原序提交]
  ROB --> AR[物理寄存器]
```
看图说明：左边是顺序，中间是乱序，右边又回到顺序。ROB 那道闸门是关键——它让"乱"只发生在内部，外面看到的结果永远规规矩矩。

## 类比与实例
- 类比：乱序执行像餐厅后厨。几张单子同时进来，有的菜要等汤底，有的立刻能炒，厨师先炒能炒的，但上菜顺序仍按单子来。失效边界：后厨可以先上凉菜，CPU 的提交顺序一步都不能乱，否则程序会算错。
- 实例：A 写 R1、B 读 R1、C 写 R2，A 和 C 无关。静态流水线要让 B 等 A 算完；Tomasulo 让 C 先算，A 的结果出来后经 CDB 直接填进 B 的源操作数槽，B 立刻执行。三拍干完原本要五拍的事。

## 常见误解
- 别以为乱序执行会改变程序结果。它只改内部时序，提交顺序严格按原序。
- 别以为多发射等于多核。多发射是一条流水线变宽，多核是多条流水线各干各的。
- 别以为猜测成功率越高越好就完事。猜错的惩罚也要算，深流水线上一次猜错可能亏十几拍。

## 自测题
1. 数据相关（RAW）指？｜后一条指令要读前一条刚写的结果｜两条指令抢同一个部件｜两条指令写同一寄存器｜答案：A｜解析：写后读是最常见的数据依赖。
2. 保留站中"源操作数的指针"存的是什么？｜尚未就绪的操作数由哪个保留站单元产生｜内存地址｜指令地址｜答案：A｜解析：靠它建立生产者与消费者的关联。
3. ROB 的作用是？｜按程序原序提交结果，并支持例外精确处理｜加快取指｜扩大缓存｜答案：A｜解析：保证乱序执行的最终结果与顺序执行一致。
4. 分支目标缓冲器（BTB）提高的是？｜转移指令的预测成功率｜内存带宽｜主频｜答案：A｜解析：它记住分支最近的目标地址，供取指参考。

## 抽认卡
- 动态流水线解决什么问题？｜消除指令相关性造成的停顿
- 两种指令相关性？｜数据相关（RAW 等）与结构相关（抢部件）
- Tomasulo 三个核心部件？｜保留站、重命名寄存器、ROB
- 乱序执行的三句话？｜有序取指、乱序执行、有序提交
- CDB 的作用？｜把计算结果广播给所有等待它的保留站与寄存器
- 多发射与多核的区别？｜前者加宽一条流水线，后者是多个独立流水线

## 术语
- 数据相关：指令间因读写同一数据形成的依赖
- 结构相关：多条指令争用同一硬件部件形成的冲突
- 保留站：暂存待执行指令、按操作数就绪情况发射的单元
- 寄存器重命名：用内部寄存器副本消除假依赖的机制
- ROB：重排序缓存，按原序提交并处理例外的部件
- BTB：分支目标缓冲器，记录分支历史目标地址的预测部件

## 复习锚点
- 相关性让流水线停，重排让它不停
- 保留站乱序、ROB 收序、重命名消依赖
- 多发射加宽，转移猜测喂饱，猜错靠 ROB 擦掉
