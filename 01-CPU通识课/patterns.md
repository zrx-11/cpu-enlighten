# 模式与框架库

这本书里真正可迁移的东西，不是那些型号和数字，而是作者反复使用的几套分析框架。学会一套，遇到新的芯片新闻也能自己判断。

## 框架：Inside / Outside

龙芯 2012 年提出的二分法。Inside 是芯片之内的 CPU 核，考验设计与工艺；Outside 是芯片之外的软件生态，考验组织与耐心。芯片是两者的衔接点。

**怎么用**：看任何一家 CPU 公司的实力，两边各打一次分。只有 Inside 强，那是实验室；只有 Outside 强，那是代理商；两边都强，才是产业玩家。

**边界**：这个模型对通用 CPU 成立得最好；纯专用芯片（如某些 MCU）Outside 很薄，用它评估会失真。

## 框架：兼容的三处支点

Intel 的成功不在跑分，而在于同时在三个地方保持向下兼容：指令集只增不删、PC 整机标准开放给所有厂商、操作系统对应用保持 API 稳定。

**怎么用**：判断一个生态能不能长期存活，挨个看这三处有没有断。断一处，应用就开始流失。

**边界**：兼容会积累历史包袱，架构老化时改不动。这也是 RISC-V 强调"没有包袱"的原因。

## 框架：生态三原则

开放、兼容、优化。开放壮大力量，兼容积累成果，优化提升体验。

**怎么用**：诊断一个生态的病，先看是哪一条缺了。Linux 是开放满分、兼容与优化不及格；苹果是优化满分、开放不及格；Wintel 是兼容满分。

**边界**：三条不是平均用力。处于不同阶段的企业优先级不同——起步期最缺开放，成熟期最缺优化。

## 框架：性能三因子

性能 ≈ 主频 × 每拍执行指令数 × 并行度。三者互相牵制：提主频要加深流水线，深流水又拉低每拍有效指令数；加宽发射要更多端口与缓存，面积和功耗随之上涨。

**怎么用**：看到"性能提升 X%"的宣传，先问是哪一项带来的，代价是什么。

**边界**：这是稳态吞吐的近似。遇到突发、串行、I/O 密集的场景，三因子解释不了全部。

## 框架：产品化的三个先后

先通用后专用、先单核后核数、先设计能力后先进工艺。这是龙芯从学院派转向产品后的排序。

**怎么用**：当一个团队把资源压在"浮点峰值""核数""先进工艺"上时，用这三条检查它是否在追指标而不是追体验。

**边界**：对科学计算、AI 训练这类真需要专用能力与堆核的场景，顺序要反过来。

## 框架：试错的时间函数

创新 = f(资金, 人才, 体制机制, 时间)。前三个变量能加速迭代，但替代不了迭代。核心技术的难点在功能细节，不在科学原理。

**怎么用**：判断一个"三年赶超"的承诺是否可信，看它有没有为试错留出周期。

**边界**：这不是说慢慢来就行。方向错了，时间只会放大错误。

## 框架：成本与定价

制造成本 =（晶片 + 测试 + 封装）÷ 成品率。售价还受销量（摊薄一次性费用）与商业策略影响。

**怎么用**：看到"某芯片成本仅几美元"的说法，先问成品率与测试覆盖率假设。

**边界**：这个公式只覆盖制造侧，不含研发、生态建设、市场费用。

## 决策规则

- **要进一个新 CPU 生态吗？** 先看它有没有稳定的指令集授权条款。授权可被单方面收回的，只能做产品，不能做产业。
- **要自研指令集吗？** 只有当你能承受十年以上的生态建设与迁移成本时才选。否则先在成熟生态里做差异化。
- **要提性能吗？** 先测瓶颈在哪：单核不满，先补设计能力；访存打墙，先加缓存层次；核数不够，再谈多核。
- **要堆核吗？** 问一句"目标负载能不能并行"。办公桌面 4 核够用，服务器单核弱则堆核无效。
- **要上先进工艺吗？** 先算一遍：同工艺下设计优化能拿到多少。3A4000 与 3A3000 同工艺性能翻倍，就是例子。
- **要不要做低端产品？** 如果目标是守高端定价权，做；如果只是想走量，先算清会不会拖垮品牌与研发。
- **看到"某指标世界先进"要信吗？** 先确认那是产品指标还是单项指标。单项领先常常只是原型。

## 反模式

**用单项指标代替产品评价。** 浮点峰值、主频、核数都是单项。作者对龙芯自身这段历史的批评最狠：单一指标接近国际主流，是典型的学院派思维。替代方案是把通用处理能力、单核性能、设计能力当主线。

**把集成当成自研。** 买 IP 攒 SoC 能做产品，但不掌握核心设计。行业里叫"CPU 搬运工"。替代方案是至少在一两个关键模块上自己做，并逐步扩大范围。

**用授权架构建"自主"生态。** 用英文能写小说，但不会因此形成自己的文化。替代方案是自研指令集，同时用二进制翻译兜住存量应用。

**只做兼容产品，不做标准。** 日本 1986 年的断供是代价最清楚的一次。替代方案是参与甚至主导标准，把接口写进规则里。

**把开源当成免费午餐。** 开源降低门槛，不自动带来兼容与优化。Linux 桌面份额长期在 1% 左右，就是碎片化的账单。

**靠降价破生态怪圈。** 用户缺的是能用的软件，不是便宜的机器。降价只能延缓死亡，不能启动正循环。

**幻想弯道超车。** 书里的判断很直白：有些表面上的直道是更弯的弯道。替代方案是直道追赶，把时间当变量而不是敌人。

**把安全当成外挂模块。** 在外面加一层安全盒子，挡不住核内的漏洞利用。替代方案是把机制做进处理器核，即"内生安全"。
